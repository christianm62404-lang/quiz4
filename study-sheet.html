SQL Functions That Return Strings

Syntax skeleton

Creating a Function

CREATE OR REPLACE FUNCTION f(p text)
RETURNS text          -- the return TYPE
AS $$                 -- body is dollar-quoted
  SELECT 'Hi ' || p;
$$ LANGUAGE sql;
  • OR REPLACE = redefine if it exists.
  • params in ( ): a name + a type.
  • RETURNS text = hands back a string.
  • $$ … $$ = dollar-quote (use '…' inside with no escaping; tag as $tag$…$tag$ to nest).
  • LANGUAGE = how to run the body (sql or plpgsql).

Call it · drop it

SELECT f('Ada');      -- 'Hi Ada'
DROP FUNCTION f(text);
sql vs plpgsql

Returning a String

  • RETURNS (header) = the type; RETURN (body statement) = hands back the value.
  • LANGUAGE sql: returns its final SELECT — no RETURN keyword.
  • LANGUAGE plpgsql: BEGIN … RETURN expr; END; — must RETURN.
-- plpgsql version
CREATE FUNCTION label(n text)
RETURNS text AS $$
BEGIN
  RETURN 'Name: ' || n;
END;
$$ LANGUAGE plpgsql;
  • Type text = any length (use this). varchar(n) caps length.
  • Return a number as text → cast n::text.
  • One string = RETURNS text; many rows = RETURNS SETOF text / TABLE(…).
Inputs & locals

Parameters & Variables

  • Use a parameter by name, or by position $1, $2. Give a DEFAULT if you like.
  • Locals go in DECLARE; assign with := (not =).
  • SELECT col INTO var … copies a row's columns into variables.
  • var tbl.col%TYPE anchors the variable's type to a column.
CREATE FUNCTION tag(id int)
RETURNS text AS $$
DECLARE result text;
BEGIN
  result := 'Record #' || id;
  RETURN result;
END;
$$ LANGUAGE plpgsql;
read first, then build

The Standard Pattern

  1. DECLARE the variables you need.
  2. SELECT … INTO the row by its id.
  3. Check IF NOT FOUND → return a message.
  4. Build the string (CONCAT_WS + COALESCE).
  5. RETURN it.

concatenation & NULLs

Building the String

  • || joins text — but any NULL operand → whole result NULL. One missing column blanks the string.
  • CONCAT(…) ignores NULLs; CONCAT_WS(sep, …) joins non-NULLs with a separator. Best for info strings.
  • COALESCE(x,'N/A') = fallback when x is NULL.
  • FORMAT('…%s…', a, b) fills %s placeholders (%I identifier, %L literal, %% = %).
  • Cast: n::text, to_char(d,'YYYY-MM-DD').
'Ph: ' || NULL              --> NULL  (!)
CONCAT_WS(' | ','Ada',NULL) --> 'Ada'
'Ph: ' || COALESCE(ph,'N/A')

Querying Inside

  • SELECT col INTO var FROM t WHERE …; — one row → variables (in order).
  • No match → var is NULL; test IF NOT FOUND THEN …. INTO STRICT errors unless exactly one row.
  • string_agg(expr, ', ') folds many rows into one string (add ORDER BY).
SELECT string_agg(product_name, ', ')
  INTO items
  FROM order_lines
 WHERE order_id = oid;
-- items = 'Bolt, Nut, Washer'
end to end · NULL-safe

Complete Example

CREATE OR REPLACE FUNCTION
  get_customer_info(cid int)
RETURNS text AS $$
DECLARE nm text; em text; n int;
BEGIN
  SELECT name, email INTO nm, em
    FROM customers WHERE id = cid;
  IF NOT FOUND THEN
    RETURN 'No customer #' || cid;
  END IF;
  SELECT count(*) INTO n
    FROM orders WHERE customer_id = cid;
  RETURN CONCAT_WS(' | ',
    'Name: '   || nm,
    'Email: '  || COALESCE(em,'N/A'),
    'Orders: ' || n);     -- n cast by ||
END;
$$ LANGUAGE plpgsql;

SELECT get_customer_info(1);
-- 'Name: Ada | Email: ada@x.com | Orders: 3'
don't lose points

Pitfalls & Volatility

  • || with a possibly-NULL column and no COALESCE → NULL string.
  • Missing RETURN on some path in plpgsql → run-time error.
  • Missing LANGUAGE, or sql with a BEGIN/END body.
  • Return-type mismatch → cast with ::text.
  • SELECT INTO many rows → only first kept (or STRICT errors).
